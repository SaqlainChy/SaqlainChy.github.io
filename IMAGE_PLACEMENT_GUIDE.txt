============================================================
SUPPORTED IMAGE FILES AND GENERAL RULES
============================================================

The project image loader in script.js accepts these extensions (case-
insensitively): .png, .jpg, .jpeg, and .webp.

Use lowercase filenames, hyphens, and exact relative paths. Do not rename
existing working files just to match these examples. For each configured
image, write a useful alt description of what is visible; the alt value is
used for accessibility and should not be a filename such as "image1".

The configured images are responsive and use object-fit: cover in their
frames. Choose a source aspect ratio close to the recommendation below so
important content is not cropped. A bad or missing configured image logs a
console message; project text and dialogs remain in place.

                      readable at the card size where possible.
REQUIRED/OPTIONAL:    Optional. An empty list shows the carousel empty state.
STATUS:               [ACTIVE]
DISPLAY:              Clickable cards in the Achievements carousel. It does
                      not open a separate image page or lightbox.

CURRENTLY REGISTERED FILES:
  assets/images/achievements/achievement-01.png
  assets/images/achievements/achievement-02.png
  assets/images/achievements/achievement-03.png

ADD AN ACHIEVEMENT:
  1. Put the image in assets/images/achievements/.
  2. Use a clear filename, for example achievement-04.png.
  3. Open script.js and find portfolioImages.achievements.
  4. Add one object to that array, keeping the comma between entries:

     { src: 'assets/images/achievements/achievement-04.png', alt: 'Describe the award or event' },

WHAT THE FIELDS MEAN:
  src = path to the image file, relative to the project root.
  alt = useful accessible description of the achievement shown.
  Array order = initial carousel order. Autoplay advances by array order.

BEHAVIOR:
  The JavaScript in script.js builds carousel cards from
  portfolioImages.achievements. The active image is centered and larger;
  neighboring images become smaller. Autoplay advances one entry every 3.6
  seconds. Hover/focus pauses autoplay. Clicking an image centers and selects
  it, pausing autoplay; clicking outside resumes from the current image.
  Arrow keys and horizontal touch swipes also navigate. Reduced-motion
  preference disables autoplay and slide transitions. A missing image is
  removed and logged; it does not become a broken-image icon.


============================================================
PROJECT IMAGES: HOW THE EXISTING SYSTEM WORKS
============================================================

PROJECT CARD versus PROJECT DETAIL VIEW
---------------------------------------
Each project card has a data-dialog attribute. Clicking it opens its existing
native <dialog> detail view. A configured main image can be shown both as a
small project-card thumbnail and as the featured image inside that dialog.
It never replaces the dialog or project information.

The current flow is:

  Project Card
      -> click / keyboard activate
      -> existing project detail dialog
      -> title and description
      -> featured main image (if configured)
      -> existing project information and subsections
      -> configured Media Gallery images (if configured)
      -> technologies and remaining content

The project details are HTML in index.html. Image configuration is centralized
in script.js under portfolioImages.projects. The five object keys are uav,
zoomController, quadcopter, motorDriver, and nabik.

MAIN IMAGE:
  projects.<key>.main.src is the image path.
  projects.<key>.main.alt is its accessible description.
  It fills the .media-wide featured-image frame inside that project's dialog
  and is also used for the project-card thumbnail when configured.

GALLERY:
  projects.<key>.gallery is an array of additional images. These are inserted
  into that same dialog's Media Gallery section, in array order. Empty [] is
  valid and hides that project's otherwise-empty Media Gallery section.
  Each gallery item has src and alt. The code creates/removes gallery slots to
  match the configured array length.

PROJECT MAPPING TEMPLATE (EXAMPLE / FUTURE STRUCTURE):
  <key>: {
    main: {
      src: 'assets/images/PROJECT_FOLDER/main.jpg',
      alt: 'Description of the featured project image',
    },
    gallery: [
      {
        src: 'assets/images/PROJECT_FOLDER/gallery-01.jpg',
        alt: 'Description of the additional project image',
      },
    ],
  },

Place that object inside portfolioImages.projects in script.js, replacing the
current value for the matching key. Keep all five existing project keys.

IMPORTANT PLACEMENT LIMIT:
  The centralized mapping currently supports only the featured .media-wide
  slot and the .media-gallery slots. Other image-looking frames in CAD,
  electronics, PCB, and technical-implementation subsections are labeled HTML
  placeholders; they do not currently read projects.<key>.gallery. To put an
  image in one of those specific subsection frames, code changes are required
  to add a mapping for that slot (or the HTML placeholder itself must be
  explicitly edited). Do not expect the project gallery array to fill those
  frames.

PROJECT VIDEO FILES — IMPORTANT: HTML EDITING IS REQUIRED
============================================================

The project detail views each contain a Video / Demonstration section and a
.video-placeholder. A commented HTML5 <video> example is inside each
placeholder. There is NO JavaScript video configuration array and NO automatic
folder scanning. Copying a video into assets/videos/ alone will not display it.

VIDEO STATUS:          [PLACEHOLDER] for all five projects
VIDEO FOLDERS:         One existing folder per project (listed below)
CURRENT VIDEO FILES:   None; folders currently contain only .gitkeep files
PLAYER:                Native HTML5 <video controls>
JS REQUIRED:           No. Edit the corresponding video placeholder in
                       index.html and set the <source src> path.
CLICK ACTION:          Native video controls play/pause/seek; it does not open
                       another page or project dialog.

RECOMMENDED VIDEO FILE:
  demo.mp4 using H.264 video and AAC audio, where possible.
  WebM can be provided as an additional source for browsers/codecs that support
  it. The website code currently does not validate video extensions.

RECOMMENDED VIDEO DIMENSIONS:
  1920 x 1080 px (16:9) source video. The player is responsive and its CSS
  sets a 16:9 display ratio. Other source ratios can be letterboxed/cropped by
  the browser/display styling; prepare the video in 16:9 for the intended fit.

VIDEO FOLDER MAP:
  UAV:                         assets/videos/uav/
  Motorized Zoom / Focus:      assets/videos/zoom-controller/
  Custom Quadcopter:           assets/videos/quadcopter/
  MOSFET Motor Driver PCB:     assets/videos/motor-driver/
  Nabik:                       assets/videos/nabik/

HOW TO ADD A VIDEO (repeat for the desired project):
  1. Put the file in the matching folder, for example:
       assets/videos/uav/demo.mp4
  2. Open index.html and find that project's comment, for example:
       <!-- UAV DEMO VIDEO -->
  3. Inside the following .video-placeholder, replace its placeholder span,
     small instruction, and commented <video> sample with the live markup below.
     Keep the outer <div class="video-placeholder"> wrapper and its closing tag.
  4. Set the source path to the exact file you added.

HTML TO INSERT (MP4):
  <video controls preload="metadata" playsinline aria-label="UAV flight demonstration">
    <source src="assets/videos/uav/demo.mp4" type="video/mp4">
    Your browser does not support HTML5 video.
  </video>

OPTIONAL MULTIPLE FORMATS:
  <video controls preload="metadata" playsinline aria-label="UAV flight demonstration">
    <source src="assets/videos/uav/demo.webm" type="video/webm">
    <source src="assets/videos/uav/demo.mp4" type="video/mp4">
    Your browser does not support HTML5 video.
  </video>

Change the aria-label to describe the actual clip and use the matching project
folder. The wrapper's responsive sizing and the .project-detail video rules
style the active player. If the video does not play, check the exact path,
file extension, browser codec support, and that the live <video> is not still
inside an HTML comment.

EXISTING PLACEHOLDER EXAMPLE IN index.html:
  <div class="video-placeholder">
    <span>UAV DEMO VIDEO</span>
    <small>Add an HTML5 video source from assets/videos/uav/</small>
    <!-- <video controls preload="metadata"><source src="assets/videos/uav/demo.mp4" type="video/mp4">Your browser does not support HTML5 video.</video> -->
  </div>

Because the <video> line is commented out, the file is currently not played.
Uncomment/replace the placeholder using the live markup above.

============================================================
I HAVE A NEW IMAGE — WHERE DOES IT GO?
============================================================

If it is your profile photo:
  Replace assets/images/profile.jpg. No JavaScript edit.

If it is an achievement/certificate:
  Put it in assets/images/achievements/ and add one entry to
  portfolioImages.achievements in script.js.

If it is the main image for one of the five projects:
  Put it in that project's assets/images/<folder>/ and update that project's
  main.src in portfolioImages.projects in script.js. It appears in the card
  thumbnail and featured image frame inside the existing detail view.

If it is another image for a project:
  Put it in the project folder and add a { src, alt } entry to that project's
  gallery array. It appears in that dialog's Media Gallery section.

If it is a CAD, electronics, PCB, testing, or field-test image for a specific
detail subsection:
  The corresponding visual frame may exist as [PLACEHOLDER], but the current
  centralized image mapping does not target these frames. Ask Codex to connect
  the desired labeled frame before expecting a configured path to display.

If it is a project demonstration video:
  Put it in the matching assets/videos/<project-folder>/ directory, then edit
  the project's commented video placeholder in index.html. See the video
  instructions above. Copying the file alone does not activate it.

If it belongs to Experience, Skills, About, Education, or Contact:
  Those sections are [NOT SUPPORTED] for file-based images in the current site.
  Code changes are required before adding an image there.
